## 2. Todo 635 — Local Test Env via Root `justfile`

### Problem
No root workspace. Each plugin + installer has its own `pyproject.toml` with path deps on `plugins/_shared`. Local dev skips `uv sync` → 24 tests fail locally (13 contract errors: `respx`; 4 worktree failures: `hook_dispatch`; 7 installer errors: `textual`). CI passes because CI runs `uv sync` per plugin.

### Design

**New file**: `/justfile` at repo root. Per-plugin `justfile`s in `plugins/proj/server/` and `plugins/worktree/server/` remain.

**Recipes**:
- `just sync` — iterate `installer/`, `plugins/_shared/`, then `plugins/<name>/server/` for each plugin → run `uv sync --all-groups` in each directory.
- `just test` — iterate the same directories → `uv run pytest` in each; does NOT fail-fast (runs all then aggregates).
- `just ci` — `sync` + `test` (local mirror of CI's per-plugin test matrix).
- `just help` / `default` — list recipes via `just --list`.

**Iteration strategy**: explicit ordered plugin list (not glob) so `_shared` installs first; other plugins reference it as a path dep and installing `_shared` first ensures its wheel is available.

Order: `installer`, `plugins/_shared`, `plugins/router/server`, `plugins/proj/server`, `plugins/worktree/server`, `plugins/todoist/server`, `plugins/trello/server`, `plugins/jira/server`.

**No per-plugin venv sharing**: each `uv sync` creates/refreshes its own `.venv` per the existing layout.

### Success criteria
After a fresh clone, `just sync && just test` succeeds locally with the same pass count as CI (all plugin test suites green). `grep -n 'respx\|textual\|hook_dispatch' local pytest output` shows no import errors.

### Files
- **New**: `/justfile`
- **Patch**: `README.md` — "Local dev" section references `just sync` + `just test`.

### Why not uv workspaces
Invasive: each plugin currently ships with its own packaging and independent version. Moving to workspaces would couple version bumps and disrupt the plugin publishing model. The `justfile` approach is additive and reversible.

### Risks
- First `just sync` on poor connectivity is slow (~same as 8 × `uv sync`). Mitigation: recipes run `uv sync` per directory individually so the user sees which plugin failed.
- Developer environments without `just` installed need a one-line install note in `README.md`.

## 3. Todo 651 — Router Sync-Layer Dedup Guard

### Problem
`~/.claude/hooks.yaml` can re-accumulate duplicate `hook_id` entries on re-register cycles (plugin reinstalls, `router_sync_tool` flushes). The existing `HookRegistry.deduplicate_numeric_hooks()` only collapses numeric `hook-NNN` entries that duplicate a named hook — it does not detect two entries sharing the **same** named `hook_id`. Todo 646 manually cleaned up the accumulated duplicates but did not add a guard against re-accumulation.

### Design

**New method** on `HookRegistry` at `plugins/router/server/server/lib/models.py`:

```python
def deduplicate_by_hook_id(self) -> list[str]:
    """Collapse multiple hooks sharing the same hook.id down to a single entry.

    Keep-rule (in order):
      1. Prefer the entry whose `server` is populated and matches a plugin default
         (server name appears in DEFAULT_SERVER_PORTS). This biases toward the
         plugin-owned canonical entry.
      2. On tie, keep the last occurrence in list order (freshest re-registration).

    Returns the list of removed hook_ids (each id appears once per removal).
    """
```

**Wire into sole write path**. `plugins/router/server/server/lib/storage.py::save()`:

```python
def save(registry: HookRegistry, path: Path | None = None) -> Path:
    target = path or _HOOKS_FILE
    removed = registry.deduplicate_by_hook_id()
    if removed:
        logger.warning(
            "hooks.yaml dedup-by-id: collapsed duplicate hook_ids: %s",
            ", ".join(sorted(set(removed))),
        )
    data = registry.to_dict()
    content = yaml.dump(data, default_flow_style=False, sort_keys=False)
    _atomic_write(target, content)
    return target
```

Because `save()` is the single write path, this catches `run_discovery`, recovery flows, and any future writer without additional wiring.

**Log level**: `WARNING`. User-visible in any log stream the router emits to. Not silent so that re-accumulation sources can be diagnosed later.

**Idempotent**: if no duplicates, `deduplicate_by_hook_id()` returns empty list and does not modify the registry.

### Test plan

**Unit tests** at `plugins/router/server/tests/test_models_dedup_by_id.py` (new file):
- 2 entries same `hook.id` → dedup returns 1 id, registry has 1 hook, correct keep-rule applied (canonical `server` wins).
- 3 entries same `hook.id`, none canonical → dedup keeps last in list order.
- 2 entries same `hook.id`, both canonical → dedup keeps last in list order (tiebreak).
- No duplicates → returns `[]`, registry unchanged.
- Mixed: 1 set of named dupes + 1 set of numeric dupes → `deduplicate_numeric_hooks()` + `deduplicate_by_hook_id()` compose correctly; net registry contains 1 entry per id.

**Integration test** in existing router storage tests:
- `storage.save(registry)` with a synthetic duplicate registry → file on disk contains only the kept hook; the warning appears in captured logs.

### Files
- **Patch**: `plugins/router/server/server/lib/models.py` (add `deduplicate_by_hook_id`).
- **Patch**: `plugins/router/server/server/lib/storage.py` (call dedup in `save()`; log warning on removal).
- **New**: `plugins/router/server/tests/test_models_dedup_by_id.py`.
- **Patch**: existing router storage test module — add `save()` integration assertion.

### Risks
- Keep-rule edge case when both duplicates have canonical `server`. Mitigated by explicit list-position tiebreak and a dedicated unit test.
- `save()` is called frequently; dedup must be cheap. Complexity is O(n) over `registry.hooks`; n is typically < 100. Acceptable.

## 4. Todo 648 — Delete `installer.claudemd` Shim

### Problem
`installer/claudemd.py` is a re-export shim kept since 639's pivot that moved the managed-section logic to `plugins/_shared/claudemd/`. Four importers still reference the shim:

- `installer/wizard.py`
- `installer/app.py`
- `installer/tests/test_claudemd.py` (220 lines; includes shim-specific path-resolution tests)
- `installer/tests/test_integration_screens.py`

The shim adds no value and complicates the import graph.

### Design

Follows todo 648's notes verbatim:

1. **Rewrite imports** in `installer/wizard.py`, `installer/app.py`, and `installer/tests/test_integration_screens.py`: replace `from installer.claudemd import X` / `import installer.claudemd as claudemd` with `from claudemd import X` / `import claudemd`.
2. **Delete** `installer/claudemd.py`.
3. **Delete** `installer/tests/test_claudemd.py`. The path-resolution tests that hardcode the shim become meaningless; other behavioral assertions duplicate tests already in `plugins/_shared/tests/test_claudemd_package.py`.
4. **Audit + extend** `plugins/_shared/tests/test_claudemd_package.py`. Before deleting the installer test file, diff its assertions against the `_shared` test file. Migrate any unique assertions (e.g., `ensure_managed_section` creates missing file, appends after user content, idempotency under repeated calls) so line/branch coverage of `plugins/_shared/claudemd/claudemd.py` does not regress.
5. **Verify** via `just sync && just test` (after 635 lands; before that, `uv sync` per affected dir).

### Success criteria
- `grep -rn 'installer\.claudemd' --include='*.py'` returns zero matches across the repo (excluding docs + frozen spec history).
- `plugins/_shared/tests/test_claudemd_package.py` line + branch coverage of `plugins/_shared/claudemd/claudemd.py` is ≥ the pre-change combined coverage of the two test files.
- All plugin + installer test suites green.

### Files
- **Patch**: `installer/wizard.py`, `installer/app.py`, `installer/tests/test_integration_screens.py`.
- **Delete**: `installer/claudemd.py`, `installer/tests/test_claudemd.py`.
- **Patch/extend**: `plugins/_shared/tests/test_claudemd_package.py`.

### Risks
- Missed importer outside the 4 known sites. Mitigated by the grep-based acceptance check and CI's full test run; an ImportError is loud.
- Coverage regression hidden by missing assertions. Mitigated by step 4's explicit audit of deleted tests before removing them.

## 5. Sequencing, Testing, Rollback

### Sequencing

1. **635 first**. No dependencies. Landing this unblocks reliable local testing for the other two branches.
2. **651 + 648 in parallel**. Disjoint file sets (router vs. installer); can merge in either order once 635 is available locally.

Each branch is independently mergeable via a separate PR.

### Per-branch acceptance checklist

- [ ] `just sync && just test` green locally (for 635: manual `uv sync` per dir until that branch itself merges).
- [ ] PR commit message follows project convention: `feat(635):`, `fix(651):`, `refactor(648):`.
- [ ] Worktree removed (`wt_remove`) after merge.
- [ ] Relevant CHANGELOG entry if the change is user-visible (635 yes; 648 internal; 651 internal with log-visible behavior).

### Rollback
- Each change is a single branch; `git revert <merge-commit>` per PR.
- 635 is additive (one new file); revert deletes it.
- 651 adds one method + two-line `save()` change; revert restores prior `save()` body.
- 648 can be undone by restoring the shim file and the four import statements.

### Out-of-band concerns
- If CI introduces a new plugin between 635's design and merge, `/justfile` must be updated to include it. Caught by the test job failing to discover the new plugin's tests.
- If `deduplicate_by_hook_id` interacts unexpectedly with `deduplicate_numeric_hooks` in a particular registry state, the combined unit test from Section 3's test plan exercises that compose path.
